What the data shows

Twelve months of customer orders, supplier purchases and month-end stock, analysed with Python.

Linear regression against random forest

  1. Added up the units sold for each medicine in each month: 780 product-months.
  2. Gave both models the same inputs: last month's demand, the product's average so far, price, season flags (flu season, vaccine peak, summer, Ramadan, December), category, storage type and dosage form.
  3. Trained each on Dec 25 to Jun 26 and tested on Jul 26 to Sep 26, months they had never seen. The random forest uses 300 trees with fixed settings, not tuned on the test months.
  4. Compared both with two simple rules: repeat last month, or use the product's average.
  5. Retrained both on all months to forecast Oct 26 to Dec 26.

Reading the results

Random forest has the lower error on the test months: 30.3% against 31.8% for the linear regression. The gap is 1.5 points, so on this much data the two are close. Demand for the typical medicine swings about 38% from month to month, which limits any simple model.

Dec 26 is the highest forecast month. Seasonal lifts were learned from a single year, so treat the forecast as an estimate. Expiry dates and supplier lead times are not model inputs, so check them before ordering.

Built with Python (pandas, scikit-learn, matplotlib) from six datasets: product master, customers, customer orders, suppliers, purchase orders and the monthly inventory ledger. All values are sample data generated for demonstration. Medicine names are generic and prices are illustrative.

Limits: both models have only 12 months of history, so neither can fully learn seasonal patterns, and a random forest cannot predict beyond the range it has seen. Two or more years of data would make the forecast more reliable.
